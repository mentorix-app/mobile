# Mentorix — термины и бренд

Источник: ответы разработчика дашборда (`docs/dashboard_answers.md`), схема API
(`docs/openapi.yaml`), палитра из `globals.css`, логотипы из `assets/icons/`.
Документ нужен, чтобы экраны тренировок говорили на том же языке, что и дашборд, и
выглядели как тот же продукт. Бренд-гайда в репозитории нет — это всё, что известно.

*Состояние на 2026-10-20 (первая версия — 2026-10-19; добавлены полный список типов
блоков, категории и сложность, поля упражнения).*

## 1. Термины программы

Тренер собирает программу в дашборде, клиент видит её в приложении. Названия
частей программы должны совпадать слово в слово.

| Часть | RU | EN | Примечание |
|---|---|---|---|
| Неделя | Неделя N | Week N | N — номер недели |
| День | День N | Day N | в заголовке результата: «Неделя {week}, день {day}» (день с маленькой буквы) |
| Блок | Блок | Block | у блока есть тип (ниже) |
| Упражнение | Упражнение | Exercise | |
| Подходы | Подходы | Sets | |
| Повторы | Повторы | Reps | |
| Инструкция | Инструкция | Instruction | пояснение к упражнению |

### Типы блока

В редакторе дашборда названия **только английские**, переводить их в приложении
придётся самим. В API тип — `block_type` в snake_case (`ProgramBlockType` в
`openapi.yaml`); в интерфейс идёт подпись из ARB по этому ключу, а не сам ключ.

Разработчик дашборда назвал по-русски четыре типа (в таблице — «дашборд»):
«Одиночный», EMOM, AMRAP, «На время», «Суперсет». Остальное — **предложение**, его
нужно подтвердить у тренеров/разработчика дашборда: у терминов CrossFit в русской
речи нет единого перевода, поэтому устоявшиеся аббревиатуры оставлены латиницей.

| `block_type` | Название в дашборде | RU | EN | Откуда RU |
|---|---|---|---|---|
| `single` | — (упражнение без группы, см. ниже) | Одиночный | Single | дашборд |
| `emom` | EMOM | EMOM | EMOM | дашборд |
| `amrap` | AMRAP | AMRAP | AMRAP | дашборд |
| `for_time` | For Time | На время | For Time | дашборд |
| `superset` | Superset | Суперсет | Superset | дашборд |
| `intervals` | Intervals | Интервалы | Intervals | предложение |
| `chipper` | Chipper | Чиппер | Chipper | предложение (термин не переводится) |
| `ladder` | Ladder | Лесенка | Ladder | предложение |
| `death_by` | Death By | Death By | Death By | предложение (название формата, не переводится) |
| `complex` | Complex | Комплекс | Complex | предложение |
| `skill_work` | Skill Work | Работа над навыком | Skill Work | предложение |
| `strength` | Strength | Силовая часть | Strength | предложение |
| `conditioning` | Conditioning | Кондиционная часть | Conditioning | предложение |
| `gymnastics` | Gymnastics | Гимнастика | Gymnastics | предложение |
| `weightlifting` | Weightlifting | Тяжёлая атлетика | Weightlifting | предложение |

- **Одиночный.** В редакторе у упражнения без группы нет типа блока, а схема API
  знает `single`. Предположение: такие упражнения приходят блоками `single` по одному
  упражнению — **проверить по живому JSON** (`docs/samples/client_program.json`).
- По умолчанию при группировке в редакторе ставится `complex`.
- Неизвестный `block_type` (тип добавят на сервере раньше приложения) не должен ронять
  экран: показывать запасную подпись «Блок».
- В EN-подписях регистр как в дашборде: «For Time», «Death By», «Skill Work».

### Категории и сложность программы

Поля `category` и `difficulty` приходят ключами и могут быть `null`. В дашборде они
английские; перевод — предложение.

| Ключ | EN (дашборд) | RU (предложение) |
|---|---|---|
| `weight_loss` | Weight loss | Похудение |
| `muscle_gain` | Muscle gain | Набор массы |
| `rehabilitation` | Rehabilitation | Реабилитация |
| `endurance` | Endurance | Выносливость |
| `functional` | Functional | Функциональная |
| `beginner` | Beginner | Начинающий |
| `intermediate` | Intermediate | Средний |
| `advanced` | Advanced | Продвинутый |
| `expert` | Expert | Эксперт |

### Упражнение и блок: что приходит

- Поля упражнения: `sets`, `reps`, `instruction`, названия `exercise_name` /
  `exercise_name_ru`. Картинок у упражнений в клиентском API **нет**.
- `sets` и `reps` — **строки**, а не числа, и могут быть `null`: допустимы `3`, `5/4`,
  `3-6`, `8-12`. У AMRAP `sets` оставляют пустым. Ряд «3 × 10» нужно собирать из
  строк и не падать на `null`.
- Единицы вроде калорий («15 cal») в `reps` не помещаются — редактор оставляет только
  цифры. Тренер пишет их в `instruction`, поэтому `instruction` упражнения надо
  показывать рядом с подходами и повторами, а не прятать.
- У блока своя `instruction`. Блок может быть виден только выбранным клиентам
  (`client_user_ids`): сервер отдаёт клиенту только разрешённые ему блоки, остальные
  не называет — фильтровать на устройстве не нужно.
- Названия программы, описание и упражнения — на двух языках (`name` / `name_ru`,
  `exercise_name` / `exercise_name_ru`). Язык выбирается по языку приложения; пустой
  русский вариант — показывать английский.

**Тексты клиентских экранов** (RU), которые назвал разработчик дашборда:

| Где | Текст |
|---|---|
| заголовок отметки | «Неделя {week}, день {day}» |
| блок со статистикой | «Текущая программа» |
| раздел статистики | «Результаты тренировок» |
| сообщение тренера клиенту | «Ответ тренера» |

Английские варианты этих четырёх текстов в ответе не даны.

### Что видит тренер

Это экран дашборда, а не приложения, но от него зависит, что напишет клиент и что
он получит в ответ.

- В карточке клиента вкладка «Результаты тренировок»: история списком или календарём,
  заголовок записи — «Неделя N, день M».
- Текст, который клиент оставил при отметке, показан **серым пузырём чата**: до 85%
  ширины, переносы строк сохраняются, рядом время отметки. Рядом бейдж «Текущий
  цикл».
- Если текста нет: «Клиент завершил этот день, не оставив заметки.»
- Статусы записи: «Требует внимания» и «Проверено».
- Под сообщением поле «Напишите комментарий…» и кнопка «Отправить». **Ответ один**:
  клиент увидит одно сообщение тренера, а не переписку.
- Откуда пришла отметка — из приложения или из Telegram — тренер не видит. Поэтому в
  приложении не нужно помечать «отправлено из приложения».

### Что это значит для экранов тренировок

- Переносы строк в заметке клиента сохраняются — поле ввода должно быть многострочным,
  длина до 1000 символов (контракт `backend_client_api.md`).
- Для «Ответа тренера» достаточно одного блока на день, без ленты сообщений.
- Названия программы и описание сервер отдаёт на двух языках (`name` / `name_ru`,
  `description` / `description_ru`): язык выбирается по языку приложения. Недели, дни,
  блоки и упражнения — как пришли от тренера.
- Подписи «Неделя», «День», «Блок» и т. п. — строки приложения, их нужно будет завести
  в оба ARB-файла сразу (правило проекта) по таблице выше.

### Чего в ответе нет

Спросить у разработчика дашборда до начала экранов:

1. Английские тексты: «Текущая программа», «Результаты тренировок», «Ответ тренера»,
   «Требует внимания», «Проверено», «Текущий цикл», «Клиент завершил этот день, не
   оставив заметки.».
2. ~~Полный список типов блока~~ — получен 2026-10-20 (14 типов + `single` в API,
   таблица выше). Осталось подтвердить **русские названия** из столбца «предложение».
3. Цвета статусов «Требует внимания» и «Проверено»: ни в `globals.css`, ни в ответе их
   нет (в палитре есть только `destructive`; см. раздел 3).
4. Как приходят упражнения без группы (блок `single`?) — по живому JSON, см.
   `docs/samples/`.

## 2. Бренд

Из ответа разработчика дашборда:

- **Шрифт** — Inter, подмножества latin и cyrillic.
- **Интерфейс нейтральный**: палитра shadcn, `primary` почти чёрный
  `oklch(0.205 0 0)`, есть светлая и тёмная темы, радиус `0.625rem`.
- **Фирменные цвета есть только в логотипе**, интерфейс ими не красится:

| Цвет | HEX | Где в логотипе |
|---|---|---|
| Небесный | `#0EA5E9` | знак (sky) |
| Светло-небесный | `#38BDF8` | знак (sky) |
| Лайм | `#84CC16` | знак |
| Сланцевый | `#263449` | знак; надпись в светлом варианте; фон иконки приложения |

  В тёмном варианте логотипа надпись `#F8FAFC` вместо `#263449`.
- Бренд-гайда в репозитории нет, логотипы разработчик дашборда отправил лично.

Логотипы в приложении лежат в `assets/icons/` (`full-logo.svg`, `full-logo-dark.svg`,
`mini-logo.svg`); иконка приложения и нативная заставка собраны из них
(`tool/generate_app_icons.py`, `tool/generate_splash_assets.sh`).

## 3. Сравнение с темой приложения

Тема приложения построена на `globals.css` — том же файле, что и у дашборда.
Проверка 2026-10-19: каждый цветовой токен из `globals.css` (`:root` и `.dark`)
пересчитан из oklch в HEX и сверен с `AppLightColors` / `AppColors`.

### Совпадает

| Что | Статус |
|---|---|
| Цвета светлой темы | **совпадают все** (background … sidebar-ring) |
| Цвета тёмной темы | **совпадают все**, включая `border` / `input` (белый 10% и 15%) |
| `primary` | светлая `#171717`, тёмная `#E5E5E5` — инверсия, как в дашборде |
| `destructive` | `#E7000B` / `#FF6467` |
| Радиус | `--radius` 0.625rem = 10 и вся шкала от него: 6 / 8 / 10 / 14 / 18 / 22 / 26 |
| Шрифт | Inter с кириллицей |
| Светлая и тёмная темы | есть обе, переключение по системной |
| Фирменные цвета только в логотипе | да: интерфейс нейтральный, цвета лого лежат внутри SVG |
| Цвета логотипа | `#0EA5E9`, `#38BDF8`, `#84CC16`, `#263449` — те же, что назвал разработчик дашборда |

### Не совпадает или различается

| Что | Дашборд | Приложение | Комментарий |
|---|---|---|---|
| Размеры текста | настольная колонка `globals.css`: h1 29, h2 24, h3 20, h4 18, h5 16, p 16/18, p-sm 14, p-xs 12 | мобильная колонка: h1 24, h2 20, h3 18, h4 16, h5 15, p 16, p-sm 13, p-xs 12 | **намеренно**: приложение телефонное. Совпадает с дашбордом на экране до 768 px |
| Отступы контента | 24 по горизонтали, 20 по вертикали | 9 и 8 (мобильные значения) | намеренно |
| Начертание Inter | подключается через `fonts.ts` веб-проекта (файла в репозитории приложения нет) | три статических файла `Inter_18pt` (400 / 500 / 600) | возможна едва заметная разница в оптическом размере и межбуквенных зазорах; сравнить глазами на одном экране, если важно |
| Жирность заголовков | в `globals.css` не задана | h1–h5 — `w600`, остальное — `w400` | наше допущение; у дашборда неизвестно |
| Статусы «Требует внимания» / «Проверено» | цвета неизвестны | в палитре нет токенов успеха и предупреждения, только `destructive` | нужен ответ разработчика дашборда; новый токен сначала появляется в `globals.css` |
| `sidebar-primary` в тёмной теме | синий `#1447E6` | есть в `AppColors`, нигде не используется | это не фирменный цвет: бренд-цвета только в логотипе |
| Шкала отступов `AppSpacing` 4 / 8 / 12 / 16 / 24 | в `globals.css` нет | есть | решение уровня приложения, дизайнеры не подтвердили |
| Скроллбар, `sidebar-width` | есть | нет | веб-элементы, телефону не нужны |

### Итог

Цвета, радиусы, шрифт и светлая/тёмная темы совпадают с дашбордом полностью;
расхождения либо намеренные (мобильные размеры и отступы), либо ещё не решены
(цвета статусов, подтверждение шкалы отступов, начертание шрифта). **Тема не
менялась** — документ только описывает расхождения.
