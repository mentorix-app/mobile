# Что лежит в `.claude/`

```
.claude/
├── CLAUDE.md            # правила этого проекта — читаются автоматически в каждой сессии
├── CLAUDE.template.md   # тот же свод без привязки к проекту — для нового приложения
├── commands/            # слэш-команды: /check, /stage-done
├── skills/              # скиллы: подключаются сами по описанию или вручную /<имя>
└── settings.local.json  # локальные разрешения, в git не попадает
```

## Скиллы

| Скилл | Когда подключается |
|---|---|
| `flutter-widget` | новый виджет, вынос виджета из экрана |
| `flutter-feature` | новая фича: entity → repository → datasource → cubit → экран → роут |
| `flutter-l10n` | строки, переводы, плюрали, даты, переполнения |
| `api-data` | свой REST API: dio, интерсепторы, модели, коды ошибок, пагинация |
| `screen-audit` | проверка кода на правила проекта |
| `stage-workflow` | порядок работы этапами и ведение `docs/` |
| `store-release` | подготовка к App Store и Google Play |

Скиллы подключаются автоматически, когда задача совпадает с описанием, или вручную:
`/flutter-widget`, `/screen-audit` и так далее. Команды — `/check` и `/stage-done`.

## Откуда это взялось

Свод перенесён из проекта Addicted Gym — правила проверены на живом приложении.
`CLAUDE.md` уже заполнен тем, что в проекте есть на самом деле; незакрытые решения
(бэкенд, локали, DI, роутинг) перечислены там в разделе «Решения, которые нужно
принять на старте». `CLAUDE.template.md` оставлен как чистый шаблон для следующего
проекта: копировать `skills/`, `commands/` и шаблон, затем заполнить таблицу сверху
и заменить `package:<app>/…` на своё имя пакета.
